## What you get

A rendered report at `tools/results_overview/report.html` (and a `.md` twin for GitHub).
You open it in a browser.
It shows a catalogue of every GRC fit on disk and a set of estout-style comparison tables, each one paired with a coefplot and a caterpillar plot.
Source is a single `report.qmd` file that re-renders in seconds whenever the sters change.

## What a comparison view looks like

A comparison fixes a slice (country, choice, depvar) and pits two "versions" against each other.
Each version fans across the five covariate sets (none, trend only, +female, +age$^2$, +edu), so two versions × five covariate sets = ten columns.
Columns are numbered (1), (2), ... estout-style, with a sub-header row naming the covariate set and group spanners naming the version.
Rows are statistics, in the order $\Delta_{\text{never}}$, $\phi$, $\bar\Delta$, $J$ p, then $N$, runtime, the per-trajectory $\Delta_{\underline{d}}$.
Each coefficient row shows the point estimate with significance stars and the SE in parentheses on the line below.
Stars: $*$ p<0.10, $**$ p<0.05, $***$ p<0.01.

## How you pick what goes into a comparison

Each comparison section is one declarative call.
You fix the slice and name the two versions; the five covariate sets become columns automatically.

```{python}
compare(
  fix    = {"country": "IDN", "spec3": "cuu"},       # consumption / urban
  versus = {"balanced": "bal", "unbalanced": "unb"}, # the two versions
  rows   = ["Delta_never", "phi", "Delta_avg", "J_p", "N", "runtime"]
)
```

The `versus` argument is what makes a comparison a comparison.
You give two labels and the spec keys they map to; you get back a 10-column table laid out as in the example above.

Common version dimensions you would plug into `versus`:

- balanced vs unbalanced (`balanced`/`unbalanced` in spec3)
- nominal vs real (the M4 `_r` suffix)
- main estimator vs Verdier-robust (when implemented)
- standard CIs vs weak-identification-robust CIs (when implemented)
- baseline vs with-education-controls (when implemented)
- pooled vs hukou-split (CHN only)

Only the first two have on-disk sters today.
The others slot in by adding a key to the filename grammar (or to `scrape.py`'s metadata parser) and become available as `versus` axes immediately.

## How you use it

```bash
# Re-render after a fresh estimation run:
quarto render tools/results_overview/report.qmd

# Open the result:
start tools/results_overview/report.html
```

To add a comparison, you append a section to `report.qmd`:

````markdown
## Balanced vs unbalanced, IDN consumption, urban

```{python}
compare(
  fix    = {"country": "IDN", "spec3": "cuu"},
  versus = {"balanced": "bal", "unbalanced": "unb"},
)
```
````

Re-render.
The new section appears.

## Catalogue at the top of the report

The top-of-report table is the catalogue of all fits, one row per fit, sortable.
You use it to confirm what is on disk and to spot anomalies (a missing run, a runaway runtime, a $J$ p-value that fell off a cliff).
This one stays one-row-per-run; with 100+ fits, columns don't work.
The version-as-column rule applies inside the comparison sections, where there are at most 10--15 columns.
