What changed in the GRC pipeline

A short tour of what's new, organized around the files and switches you'll open.

Change 1 / The big one

Files 10 through 15 are gone

Their regressions now live in one place, called by a single program.

Before

10_GrRC_experience.do
11_GrRC_max_experience.do
12_GrRC_experience_share.do
13_GrRC_max_experience_share.do
14_GrRC_NonAg_experience.do
15_GrRC_birth.do
→

After

9_GRC_extras.do + run_grc_with_extra_regressor in 0_programs.do

Each call inside 9_GRC_extras.do is one line:

run_grc_with_extra_regressor, country(IDN) spec3(cuu) regressor(exp)
run_grc_with_extra_regressor, country(CHN) spec3(cuu) regressor(exp)
run_grc_with_extra_regressor, country(TZA) spec3(cuu) regressor(exp)

The shared logic that used to fan across the six files now sits as one program in 0_programs.do. To add a regression of the kind that used to go in (say) 11_GrRC_max_experience.do, scroll to the max_experience section of 9_GRC_extras.do and add one call line.

Everything else about the pipeline---data prep, summary stats, OLS, main GRC, hukou GRC, learning, tables, figures---works the way you remember.

Change 2 / Filenames

The .ster files got shorter names

Old names spelled out every axis, which kept blowing past Stata's 32-character cap on internal estimate names once the subgroup suffixes (_n, _a, _d, _g) got tacked on. The new names compact depvar, choice, and balance into a three-letter token.

Before
GRC_CHN_consumption_urban_unbalanced_exp_c1.ster

48 chars; collides with the 32-char internal name cap.

After
grc_CHN_cuu_exp_c1.ster

24 chars; safe headroom for every subgroup suffix.

How to read the three-letter token

Position 1
c · i
c = consumption, i = income
Position 2
u · n
u = urban, n = non-ag
Position 3
u · b
u = unbalanced, b = balanced

So cuu reads as "consumption, urban, unbalanced"; cub as "consumption, urban, balanced"; inu as "income, non-ag, unbalanced"; and so on. Per fit you'll see five files on disk: the main .ster plus four subgroup ones (_n for never-switchers, _a for always-switchers, _d for delta switchers, _g for the group-average row).

Change 3 / Behavior knobs

Five switches at the top of 0_master.do

A handful of globals live near the top of the master. Each one is a single line you flip; the defaults are picked so the pipeline runs end to end without surprises.

$dir your user block

Project root. Set inside the if "`c(username)'" == "..." block keyed to your machine username. Everything else (scripts, data, output) lives relative to it.

$overleaf your user block

Optional. Path to your local Overleaf-Dropbox folder. If you leave it unset, copies to Overleaf simply skip with a one-line notice at the start of the run. If you set it, the pipeline uses the path whenever $copyOverleaf is on.

$copyOverleaf line ~81 of 0_master.do default: 1
1
copy tables and figures to $overleaf as they're built
0
build them locally only
$values defaults in 0_path_config.do default: nominal
"nominal"
reads $dir/data; output filenames are bare
"real"
reads $dir/data_real; output filenames get an _r suffix

The two modes coexist on disk, which helps when you want nominal and real results side by side. To pick real mode, set global values "real" in your user block above the include "$dir/scripts/0_path_config.do" line.

$runDashboard line ~86 of 0_master.do default: 0
0
skip the Python tail
1
refresh the headlines cache for the results dashboard

The pipeline finishes all tables, figures, and .ster files before this flag fires, so the default of 0 keeps Python out of the picture entirely. Flip it to 1 only if you've got Python installed and want the dashboard cache.

How to use it

Common situations

Four scenarios you'll hit, and the file to open for each.

1

Run the whole pipeline from scratch

Every fit runs unconditionally. Use this when you've changed programs and want a clean canonical run.

Open 0_master.do
2

Pick up after a crash

The main GRC fits are the slow part. run_master_resume.do flips one global so already-saved cells get skipped:

* the entire file
global skip_if_exists 1
do "0_master.do"

Data prep, OLS, table builders, and figure builders all still run; those are cheap.

Open run_master_resume.do
3

Force a clean re-fit of specific cells

Resume mode skips any cell whose _g.ster sits on disk. To force those cells to refit, delete (or move to an archive folder) the .ster files for the cells you want redone, then run run_master_resume.do again.

For a clean wipe across the board: archive the whole $output folder and run 0_master.do.

Delete or archive in $output
4

Re-fit just one subset of 9_GRC_extras.do

Three small shortcut files walk subsets of the calls in 9_GRC_extras.do. Open the matching one and run it; they share the skip-if-exists behavior, so they only refit what's missing:

  • run_extras_maxexpsh.do
  • run_extras_birth.do
  • run_extras_cnu.do
Open one of run_extras_*.do
Change 4 / Numerical fix

A small correction to the Delta_avg row

The Delta_avg row in the main GRC tables had a formula bug: it returned switcher_frac × E[Delta | switcher] instead of E[Delta | switcher]. 0_programs.do now carries the corrected formula.

What this means in practice: the corrected Delta_avg runs ~9× to 14× larger than the pre-fix value, because switcher_frac sits in the 7---11% range across countries. If you have a draft of the tables from before May 2026, that row will move on a re-run.

The affected files are 4_GrRC.do, 5_GrRC_NonAg.do, and 7_GrRC_hukou.do. Re-running the pipeline (or the resume wrapper) refreshes every affected cell automatically.

For the curious: what 0_slice_bootstrap.do does

Each run_extras_*.do file sets $dir in its own user block and then includes 0_slice_bootstrap.do, which handles the rest of the setup: it includes 0_path_config.do for sub-directory globals, quietly includes 0_programs.do (quietly because that file is large enough to flood the output otherwise), turns on skip_if_exists, and turns off copyOverleaf defensively. To write a fourth shortcut, the body of the new file is just the call sites; the bootstrap handles the rest.
