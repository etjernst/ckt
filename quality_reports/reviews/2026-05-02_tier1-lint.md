Walked every constructed estname against the 32-char ceiling.
The longest production stem in current code is `grc_<country>_<spec3>_<fam>_<col>` for the `maxexpsh` family with `ca` covs:

```
grc_TZA_iuu_maxexpsh_ca         = 23 chars stem
+ _g                            = 25 chars (longest suffix)
+ _est_                         = 30 chars  (under 32 limit)
```

Verified directly against the live ster filenames on disk: longest `_g.ster` filename stem is `grc_TZA_iuu_maxexpsh_ca_g` at 25 chars.

`grc_CHN_rural_first_ca` = 22 chars + `_g` = 24 chars + `_est_` = 29 chars.
Three chars of slack.
Still safe.

## Check 6 (added): pre-M11 orphaned sters on disk

This check is not in the spec's Tier 1 list but surfaced incidentally while running the length-budget verification.

Two pre-Phase-1a (pre-M11) naming patterns survive on disk in `C:\git\ckt\.claude\worktrees\grc-pipeline-refactor\RP7\output\`:

- **60 files with the old suffix words** matching `grc_*_always.ster` / `grc_*_never.ster` / `grc_*_delta.ster` / `grc_*_avg.ster`.
- **15 main-fit sters with the old `urban_covs_*` and `nonag_covs_*` naming** (no suffix, e.g. `grc_CHN_urban_covs_0.ster`).

75 total, spread across CHN / IDN / TZA times the five covariate levels (`covs_0`, `covs_1`, `covs_2`, `covs_trend`, `covs_all`).

These are leftovers from before commit `ddb3886` (Phase 1a / M11).
No live do-file writes them or reads them; they coexist on disk with the new-naming sters that Tier 3 #6 is actively producing.
Two specific concerns:

- **S1 ster scraper**: when implemented, it will need to filter these out by suffix match (the new scheme has 1-char suffixes `_n` / `_a` / `_d` / `_g`; old scheme has the full words) or by string match against `_urban_covs_` / `_nonag_covs_`.
- **Internal-name length**: e.g. `grc_TZA_urban_covs_trend_always` is 31 chars; with `_est_` that is 36, which busts the 32-char ceiling. No code currently does `estimates use` on these by stem, so no active error. But running `estimates use grc_TZA_urban_covs_trend_always` interactively errors with `r(7); invalid name`.

Recommended cleanup, post-Tier-3 #6:

```bash
ls RP7/output/grc_*_always.ster RP7/output/grc_*_never.ster \
   RP7/output/grc_*_delta.ster  RP7/output/grc_*_avg.ster      | wc -l
ls RP7/output/grc_*urban_covs_*.ster RP7/output/grc_*nonag_covs_*.ster | wc -l
# Confirm 60 + 15 = 75. Then delete:
rm RP7/output/grc_*_always.ster RP7/output/grc_*_never.ster \
   RP7/output/grc_*_delta.ster  RP7/output/grc_*_avg.ster
rm RP7/output/grc_*urban_covs_*.ster RP7/output/grc_*nonag_covs_*.ster
```

Defer until Tier 3 #6 closes so we know we are not deleting in-flight artifacts; confirm counts with `wc -l` before the `rm`.
