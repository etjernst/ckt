## Decisions, with the why

**Decision: launch Tier 3 #6 immediately rather than diagnose Tier 3 #5 OOM cell-by-cell.**
Why: user diagnosed the proximate cause as a parallel R process competing for RAM, not a code-side leak.
Per-cell investigation would have spent hours fingerprinting whichever cell happened to be running when system memory tightened, with no actionable code change at the end.

**Decision: archive the prior OOM log before relaunching.**
Why: `stata-mp -b` overwrites `<file>.log` by default.
The 1.8 MB Tier 3 #5 log had 28 error markers that may matter for post-mortem if the OOM recurs.
Cost of preserving was a single `mv`; cost of losing it was unrecoverable.

**Decision: separate commits per artifact rather than one bundled commit.**
Why: explicit user preference this session.
Each commit captures one logical change so the edit history is meaningful and a future bisect is tractable.

**Decision: keep human-readable .tex table names.**
Why: tables are paper-facing; sters are code-facing.
`GRC_IDN_consumption_urban_unb.tex` is recognizable to a coauthor; `GRC_IDN_cuu.tex` is not without the legend.
Renaming would also re-freeze the Tier 0 reference snapshot, which would invalidate the in-flight Tier 2 byte-identity check.

**Decision: do not delete the 75 pre-M11 orphan sters this session.**
Why: Tier 3 #6 was mid-flight, writing into the same directory.
Conservative discipline: do not `rm` from a directory with an active writer.
User later expanded scope: may wipe `RP7/output/` entirely pre-merge.

**Decision: do not auto-fix the two `tier2_table_diff.py` bugs surfaced by the dry-run.**
Why: project rule (`~/.claude/rules/script-safety.md`) requires user approval for script bug fixes.
Even though the bugs are in code I wrote in this session, the rule is path-scoped to all scripts.
Cost of waiting (a few hours or a session) is low; value of preserving the rule is meaningful.

**Decision: the S1 ster scraper uses a Stata-side dumper plus Python wrapper, not the spec's `pyreadstat` Python-only design.**
Why: `pyreadstat` reads `.dta` files, not `.ster`.
The spec was wrong on this point.
Stata reads `.ster` natively, so a thin `.do` loop is shorter and more obviously correct than wrestling `pystata` initialization on every scraper run.
Python side enriches with filename parsing, mtime, git commit columns.

**Decision: write the wrap-up log even though the session was largely waiting + heartbeat checks.**
Why: the multi-day arc has too many open items to leave implicit.
Future-Claude will need the seven open user-input gates spelled out, otherwise the work fragments across two prior session logs.
